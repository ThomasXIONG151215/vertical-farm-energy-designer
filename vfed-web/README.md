# vfed-web — Browser Frontend

The VFED web UI runs **entirely in the browser**: a Pyodide Web Worker embeds the `vfed/` engine, so there is no backend server and no Python runtime needed on the client. Weather comes from pre-downloaded CSVs (`data/weather/`) plus optional browser-side Open-Meteo fetch.

> 中文版说明见 [README_zh.md](README_zh.md)。

## Run locally

```bash
cd vfed-web
npm start          # serves http://localhost:8000/ (python -m http.server 8000)
```

Then open <http://localhost:8000/> in a modern browser.

- **Do not** open `index.html` directly via `file://` — the Web Worker and CSV fetches require an HTTP origin.
- The **first load needs internet**: Pyodide (v0.27.0) is pulled from the CDN (`jsdelivr`). Chart.js is served locally from `public/libs/` with a CDN fallback.
- After the worker is ready, pick a preset (**609 — Fengxian Lettuce PFAL** or **Lettuce — Standard PFAL**), adjust parameters, and hit **Run Simulation**.

## Rebuild the worker (`worker.js`)

`worker.js` is generated by embedding the `vfed/` sources:

```bash
cd vfed-web
npm run build      # runs python bundle.py
```

**You must rebuild** after changing anything under `vfed/` or refreshing `data/weather/` — the browser never sees your working tree directly.

## Deploy (Cloudflare Pages)

```bash
cd vfed-web
npm run deploy     # builds, then: wrangler pages deploy --project-name vfed-web
```

## Simulation flow

1. The UI generates a project YAML from the form (`generateYaml`).
2. The YAML is `postMessage`-ed to the Pyodide Web Worker (`worker.js`).
3. The worker runs the `vfed` engine in-browser and returns the result JSON (including `weather_attrs` weather provenance).
4. Charts render with Chart.js; the result panel shows the weather source line.

## Smoke tests (Playwright, dev-only)

`test.js` and `test_comprehensive.js` drive a headless Chromium against a locally served instance:

```bash
npm start                                   # terminal 1
node test.js                                # terminal 2 (note: targets port 8080)
node test_comprehensive.js                  # full interaction pass
```

Both scripts wait for worker init (Pyodide + packages take ~1 min on first load), click **Run Simulation**, and log console/worker output. They are ad-hoc dev tools, not part of CI — the authoritative test suite is `pytest` at the repo root.
