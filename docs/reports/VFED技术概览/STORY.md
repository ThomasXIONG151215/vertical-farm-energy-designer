## 四页结构

- **P1 总览 · 架构图**：三层纵向（左侧 104 宽的层标签列贯穿到底，右侧内容统一从左对齐）
  - 层 1 输入：一张横条卡内 5 组参数格（城市与气候 / 围护构造 / 设备 / 作物 / 电价与投资），右端「参数全部可扫」小标。
  - 层 2 模型：三张卡（传热传质 / 作物生长 / 电能调度），每卡「三行人话等式 + 底部产出端口（浅底条）」。
  - 层 3 指标：四张薄荷底卡 —— **总产量 / 总功率 / kWh-kg / 单位用电成本**，最后一卡深绿描边收尾。
  - 两道流向注释插在层间：「积分步长 600 s（每小时内步 6 次）· 输出按小时聚合为 8760 点 · 三组方程在同一时间轴上互相取值」「逐时累计得四个指标；换参数重算就是扫参」。
  - **不再出现 LCOE**：LCOE 只是可选目标之一，不是终点；终点是四个可互相权衡的指标。
- **P2 传热传质**：三条平衡式（室温 / 含湿量 / CO₂，各挂「决定冷量 / 决定除湿量 / 决定生长」药丸）+ 三张计算细节卡
  - 一步之内按这个顺序：取边界 → 逐项算热流湿流 → 合成 Q 与 M → 先推温度再用新温度封顶含湿量 → 冷凝潜热回灌再算一次温度
  - 湿与热是同一笔账：Magnus 反算饱和压/相对湿度/露点；蒸腾按汽化潜热扣冷负荷；含湿封顶溢出即冷凝水；析水把潜热放回来
  - 为什么敢用显式欧拉：步长远小于房间热容与含湿时标；三处钳位都回传残差（温度残差 / 触底水量 / 冷凝水量）；步长减半结果不变
- **P3 作物**：两卡（干重 / 失水）+ 步内闭环条 + 三栏（状态与边界 / 参数分组 / 输出换算）
  - 干重卡：`dX = 碳转化率 × 光合 − 暗呼吸`；光合 = 冠层截光 × 光碳联合限制项（A·B/(A+B)，谁紧谁主导）；截光随干重饱和；呼吸随温度指数上升
  - 失水卡：`E = k × 干重 × 饱和差 × 冠层面积`；饱和差由室内温湿度算出，气候一变失水立刻变；光期开孔、暗期折减；水同时进湿负荷与潜热
  - 步内闭环：上一步状态（PAR·CO₂·室温）→ 冠层截光 → 光合减呼吸 → 干重增量 → 干重×饱和差 → 蒸腾 → 湿负荷与潜热回到气候
  - 三栏：只有一个状态量；参数分三组全部走 YAML；干重 ÷ 干物质率 = 鲜重，只有收获那一刻算产量
  - **不放任何产量强度数值**（kg/m²·年 之类一律不出现）
- **P4 电能**：改成**三步链**（左列 104 层标签：第 1 步 / 第 2 步 / 第 3 步），回答「负荷与光储到底怎么合成单位成本」
  - **第 1 步 负荷**：三张卡用 `＋` 连起来，末端 `＝` 一个薄荷底的 **P_load(t)** 结果框（8760 点，「光储要对的那张表」）
    - LED：`P = PPFD × 面积 ÷ 光效`；PAR 与光周期由策略给定；电全转显热，再进冷负荷
    - 空调：`P = 冷量 ÷ COP`；冷量是传热方程的补偿量；COP 随外温；容量不足截断→室温漂移→反噬产量（**唯一的反向耦合**）
    - 除湿：`P = 除湿量 ÷ 有效 SMER`；除湿量是传质方程的补偿量；越干越费电；析水潜热回灌
  - **第 2 步 逐时匹配**：四个节点用箭头串成一条流水线，**净负荷节点用薄荷底 + 深绿描边强调**，并标红「负荷与供能在这里接上」
    - 光伏 `P_PV(t) = f(辐照, 板温)` → 净负荷 `net = P_PV − P_load`（正余电 / 负缺口，之后全按符号走）→ 电池（`net ＞ 0` 充、`net ＜ 0` 放，SOC 卡上下限，逐时规则匹配不做全年寻优）→ 电网（`买 = max(0, 负荷−光伏−放电)`、`卖 = max(0, 光伏−充电−负荷)`）
  - **第 3 步 结算**：一张宽卡自上而下推导
    - `单位用电成本 = 年成本 ÷ 年鲜重（kg）`
    - `年成本 = 年化投资 + 年运维 +（购电费 − 上网收益）`
    - 小注：全系统投资按部件折旧年限折等年金；运维含维保、水与人工；购电按分时电价、上网按固定电价
    - 红左条结论：**光储只动分子（投资与净购电），产量在分母上由作物与气候定——所以必须在同一次逐时仿真里算完**
  - 已删除：原来的「供能四卡」与独立的「时序错配条」（错配压成净负荷卡的一行注文）

## 每页结论（底部结论条原文）

四条统一为「判断句前置 + 一处红字落点 + 句号」，每条 26–38 字，读起来是一组：

- P1 作物、围护、设备都只是中间量，真正要比的是 **产量、功率、kWh/kg 与单位成本**。
- P2 空调与除湿的容量不是估出来的，是 **三个方程逐时解出的补偿量**。
- P3 作物只有一个状态量——干重，它同时决定 **产量与除湿电耗**。
- P4 负荷决定用多少电，光储决定这些电的价，**单位成本只能在逐时仿真里合出来**。

## 时间分辨率（三层，别混为一谈）

| 层 | 分辨率 | 实现 |
|---|---|---|
| 气象 / 电价边界 | 1 h（8760 点，小时内零阶保持） | `worldweather` 逐时序列；`T_ext[h]`、`is_light_h` 在 sub 循环内不变 |
| 物理 / 作物 / 设备积分 | **600 s（10 min），每小时 6 内步** | `space.timestep_s = 600`；`sub = 3600/dt`；全年 8760 × 6 = 52560 步 |
| 输出与光储调度 | 1 h（8760 点） | `load_kw[h] = Σ(6 内步能量)/1000`、`T_z_out[h] = 均值`；PV/电池/电价结算都吃小时数组 |

- `timestep_s` 必须整除 3600，否则 build 期直接报错（可选 600 / 900 / 1200 / 1800 / 3600）。
- 口径提醒：**「8760」是小时数，不是步数**。步数 = 8760 × (3600/600) = 52560。PPT 上曾误写「每年 8760 步」，已于 2026-10-26 修正为「积分步长 600 s（每小时内步 6 次）· 输出按小时聚合为 8760 点」。

## 公式怎么写（重要）

**用中文项名，不用变量名。** 读者不应该在附录里解码 `Q_HVAC`、`m_inf`、`Φ_phot`；等号左右都应该是能指着机器说出来的东西：

```
室温变化 ＝ （空调冷量 ＋ 除湿显热 ＋ LED 发热 ＋ 围护传热
          ＋ 太阳得热 ＋ 渗透显热 ＋ 渗透潜热 − 蒸腾潜热）÷ 房间热容
失水 ＝ 蒸腾系数 × 干重 × 饱和差 × 冠层面积 × 昼夜系数
```

被淘汰的三种写法（都试过，都不可读）：
1. `<Math>` 组件 —— 本机渲染空白；
2. 内联 `<svg>` 手绘 —— 多次 upsert 后从旧页静默消失；
3. mathtext 渲成 PNG —— 字号可以统一，但分式与下标仍需逐字辨认，附录变成"看公式"而不是"读公式"。

版式规则：

- **一个字号走到底**：主式 `EQ_FS = 16`，辅助行 `NOTE_FS = 13`（灰色 `#5E6E6B`）。只有这两级，没有别的字号。
- **主式与辅助行**：主式是"哪一项等于哪几项"，辅助行是"其中一项怎么算"或"这一步之后还会怎样"。辅助行用小灰字，视觉上紧贴上一条主式，条与条之间因此不会被误读。
- **行高按实测值算**：16px / lineHeight 1.5 实测 **30 px**，13px 实测 **22 px**。可用高度 = 500 − 2×16 − 6（安全余量）。
- **行距按剩余高度分配并截断**：余量按权重摊到各间隙（条间 1.0、小节前 2.6），再截断（条间 ≤30、小节前 ≤48），剩下的回流到上下留白。实测 A 21、B 28、C 19、D 15；小节前 48。
- **宽度自检**：`text_w()` 按「CJK 1 em、运算符 0.75 em、拉丁 0.55 em」估算，超过 662 px 打印 `eq N line too wide`，按运算符处断行（续行以 ＋ / − / ÷ 开头）。
